**S0 建房与入席（seed）** — `rooms.create({ title, scenarioKey: 'scope_change', timeZone })`（customer 身份）→ `invites.create` ×2（邮箱定向）→ provider、finance `invites.accept`。写入：rooms（`status: 'setup'`，`localDate: 2026-11-02`，`provenance: 'seeded'`）、members ×3。cv —。事件 `room_created`、`member_joined` ×3。三方："Setup · waiting for the catalog and briefs" + `SimulatedBadge`。

**S2 目录确认** — provider `catalog.confirm({ roomId, expectedConstraintsVersion: 0, rows })` 一批确认 6 行（12 §12.12，计一次节流）：每行过 `validateCatalogRow`，写 catalogItems 6 行（revision 1，`editNo 0`，`confirmed`）。setup 期不计 cv。事件 `catalog_item_confirmed { items[] }`。三方看到同一目录表（标题、价格、交付天数、Rush −4 天 +$150）。

**S3 三份简报 → 房间开放、run 1** — `briefs.confirm` 依次 provider（只有 notes）→ customer（必需 `audit_log_export`、`sso_login`；截止日 = 锚点 +18 = 2026-11-20；愿望清单；披露勾选）→ finance（`capCents: 500000`，只把 `capCents` 披露给 customer）。第三份确认在同一事务里：`openIfReady` → 房间 `open` → `constraints.bump({ cause: 'room_opened' })` 写 cv 1 → `react()` → `startRunTx({ cause: 'room_opened' })` 预检全局可行集 `[$800, $900]` 非空 → run 1 `negotiating`（`constraintsVersionAtStart 1`，`roundNo 1`）→ `createTurnTx(provider, propose, anchor)` 快照 `[O1 audit_log_export+sso_login $800 2026-11-16, O2 audit_log_export+sso_login+usage_dashboard $900 2026-11-18]` → `turns.beginAttempt`。事件 `brief_confirmed` ×3、`room_opened`、`constraints_changed { fromVersion: 0, toVersion: 1 }`、`run_started { runNo: 1, cause: 'room_opened' }`、`turn_scheduled`。C："Finance shared: budget cap $5,000"；P 与 F："Customer requires: Audit log export, SSO login (SAML) · Deadline 2026-11-20"，P 另见 "Wishlist: Slack alerts, Usage dashboard"；P 看不到任何预算数字。

**S4 provider 回合 → v1 $900** — `agents.runAttempt`（stub 选与愿望清单重合最多的 O2）→ `turns.complete`：守卫 G0–G3 通过，`materialize(O2)` → 插入 proposals v1 `{ terms: { itemKeys: ['audit_log_export', 'sso_login', 'usage_dashboard'], modifiers: [], deliveryDate: '2026-11-18', amountCents: 90000 }, termsKey, lines（revision 1 ×3）, plannedTasks ×3, requiredApprovals: [customer/terms, provider/terms, finance/budget], createdAtConstraintsVersion: 1, status: 'active', provenance: 'stub' }`；`checkProposal(全局)` 通过（490000 ≤ 500000）；`runs.currentProposalId = v1`；`createTurnTx(customer, evaluate)` 快照 `[O1 $800]`（排除 base v1 的键，05 §5.7.2）。cv 1 · v1 active · 审批 —。事件 `turn_completed { turnSeq: 1, role: 'provider' }`、`proposal_created { proposalVersion: 1 }`、`turn_scheduled`。
- C："Provider agent proposes Audit log export + SSO login (SAML) + Usage dashboard for $900, delivery 2026-11-18." · "+$900 change · finance cap $5,000." · "Not included from your wishlist: Slack alerts." · 检查：必需项 ✓、截止日 ✓（预算检查属 finance 且通过，省略）。

- F：同一句 · "+$900 change · committed $4,000 → $4,900 · cap $5,000 · headroom after $100." · 全部检查精确可见（customer 已向 finance 披露必需项与截止日）。

**S5 评估 → 待审批** — customer stub：v1 在自身视图通过，愿望重合 1 ≥ 快照最优（$800 为 0）→ `recommend_accept { proposalVersion: 1 }`；`createTurnTx(finance, evaluate)`（finance 不能 counter，无快照）→ v1 在其视图通过 → `recommend_accept`。`resolveRound`：全部建议接受且 `passesChecks(v1)` 用当前 `localDate` 重算通过 → run 1 `pending_approval`。事件 `turn_completed` ×2（他人只见 "finished"）、`run_awaiting_approval { runNo: 1, proposalVersion: 1 }`。三方："Ready for approval: v1 under constraints v1"；C、F 各自的本方代理框："Your agent recommends accepting v1. **S6 customer、provider 批准 v1** — `approvals.record({ proposalId: v1, decision: 'approve', expectedConstraintsVersion: 1, expectedTermsKey })` ×2：`isExecutable(v1) = { ok: true }`（当前性 ∧ 规则，08 §8.4.2）→ approvals a1（customer）、a2（provider），`boundConstraintsVersion 1`、`boundTermsKey(v1)`；`evaluateApprovalSet` 缺 finance → 不执行。cv 1 · v1 active · 审批 2/3。事件 `approval_recorded` ×2。三方："Waiting on: Finance (budget commitment)"；F 待办："Approve budget commitment v1 under constraints v1 (+$900)"。

**S7 finance 预览并下调上限 → cv 2** — `rooms.previewChange({ roomId, change: { kind: 'cap', newCapCents: 480000 } })`（12 §12.17）只对 finance 返回 `{ verdict: 'after', nextConstraintsVersion: 2, invalidatedApprovals: 2, willSupersedeRun: true, verdictAfter: { proposalVersion: 1, budgetCheck: 'budget.over', overByCents: 10000 } }`（形状逐字取自 12 §12.17）——只回答当前提案的预算检查，**不**回答"是否仍有可行方案"（privacy-03）。随后 `budget.setCap({ roomId, capCents: 480000, expectedConstraintsVersion: 1 })`：`validateCapChange`（480000 ≥ 400000）通过 → finance 简报 v2 → `constraints.bump`：投影变化 → cv 2；run 1 `superseded`（`endedReason: 'constraints_changed'`）；v1 `stale`；approvals 行不改（派生为 `stale_approve` ×2）；`react()` → `startRunTx({ cause: 'constraints_changed', origin: 'system', keepCandidateId: v1 })`（04 §4.3.3；run 1 被取代前处于 `pending_approval`，所以带 `keepCandidateId`）预检：沿用的 v1 在新约束下 `budget.over` → 不走 R2；全局可行集 `[$800]` → run 2 `negotiating`（`constraintsVersionAtStart 2`）；`createTurnTx(provider, propose, round 1, anchor)` 快照 `[O1 $800, O2 $900]`（不按 v1 在新 cv 下的结论剔除，D12 ①）。事件 `brief_confirmed { role: 'finance', version: 2 }`（provider 变体并入 `constraints_changed`，03 §3.11.1）、`constraints_changed { fromVersion: 1, toVersion: 2 }`（`restrictedRef → constraintRevisions`，cause `brief_confirmed`、actor finance 只对买方连接）、`run_ended { runNo: 1, status: 'superseded', endedReason: 'constraints_changed' }`、`proposal_status_changed { proposalVersion: 1, to: 'stale' }`、`run_started { runNo: 2, cause: 'constraints_changed' }`、`turn_scheduled`。`isExecutable(v1) = { ok: false, reasons: ['version.stale_constraints', 'budget.over'] }`。
- C："Finance updated the budget cap to $4,800 (constraints v2). Proposals are being re-checked." · v1 卡："This version no longer applies (constraints v2)."（stale 提案不做实时重算、不显示掩码检查，06 §8 / privacy-09）· 审批面板："Your approval no longer applies · approved under constraints v1"。

**S8 provider 两轮 → v2 $800** — 第 1 轮 stub 依愿望清单选 O2（$900）→ `turns.complete`：`checkProposal(全局)` 为 `budget.over`（490000 > 480000）→ **不插提案、不消耗版本号**，turn 记 `outcome.blockedCandidateKey`，不调评估（D08、03/04）；provider 只见 "Round 1: your option was blocked under the current constraints."，买方时间线 "A provider option was blocked by the current constraints."（模板 `turn.blocked`，§8.5；不含条款与金额，07 DX-1；事件 `turn_completed`，payload 无原因）。第 2 轮快照 `[O1 $800]`（剔除本 run 已提出的 $900；锚点只在第 1 轮）→ stub 选 O1 → `materialize` → proposals v2 `{ itemKeys: ['audit_log_export', 'sso_login'], modifiers: [], deliveryDate: '2026-11-16', amountCents: 80000 }`；`checkProposal(全局)`：400000 + 80000 = 480000 ≤ 480000，**恰等于上限通过**；v1 仍 `stale`；customer 评估快照为空（排除 base $800 与已提出的 $900）。cv 2 · v2 active。事件 `turn_completed`、`proposal_created { proposalVersion: 2 }`、`turn_scheduled`。

**S10 customer、provider 批准 v2** — `approvals.record({ proposalId: v2, decision: 'approve', expectedConstraintsVersion: 2, expectedTermsKey(v2) })` ×2 → a3、a4（事件 `approval_recorded` ×2）。若页面仍停在 v1 / cv 1 就点批准：run 1 已被取代，当前性守卫先失败 → `approval.not_current`、不写行（12 §12.15 ⑤ 先于 ⑦；只有"同一提案在新 cv 下被沿用"时才是 `approval.stale`，见 §11 F）。三方："Waiting on: Finance"；F 按钮："Approve budget commitment v2 under constraints v2 — your approval completes the set, this executes now."

- 三方："Change order CO-1 recorded: v2 under constraints v2, $800, 2 tasks for the provider. Internal record only — no payment, transfer or signature happens in this system."
