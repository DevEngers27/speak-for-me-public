### 1.7 执行边界（核心 7）

| ID | 谓词 | 核心 | 落点 | 违反后果 |
| --- | --- | --- | --- | --- |
| INV-59 | 代码库对外部 ERP / 支付 / 签署 / 邮件 SDK 零依赖：`package.json` 直接依赖 ⊆ 白名单（next、react、convex、@clerk/*、@anthropic-ai/sdk、zod 与 D20 列出的开发依赖）；`core/engine` 禁 `Date` / `Intl` / `Math.random` / `fetch` / `convex/*` / `zod`（ESLint 纯度规则）；`convex/executions*.ts` 与 `approvals.ts` 不 import 任何 action、HTTP 客户端或 `"use node"` 模块 | 7 | 依赖白名单测试（读 `package.json`）；`no-restricted-imports` 分层（spike 已验证） | 执行事务里"顺手"调 ERP；第二条执行路径 |
| INV-60 | 执行只写内部表：`executions`、`ledgerEntries`、`changeOrders`、`tasks`、`events` 与 `proposals` / `runs` / `rooms` 的状态字段；执行路径上没有 action、没有 `fetch`、没有 `runAfter`；代码库唯一公开 action 是邀请 token 生成（`invites.createLink`，只做随机数与哈希，经 internal `invites.authorizeLink` / `invites.insertLink` 写入；`invites.create` 是邮箱定向的 memberMutation）；v1 无 outbox 表、无 CSV 导出 | 7,5 | 结构测试：`executeIfComplete` 的写集合白名单；12 的函数目录"无公开 action（邀请除外）" | 幂等被宣称覆盖外部系统（P-05）；公式注入导出 |
| INV-61 | 变更单 DTO 与打印视图固定渲染模板 `change_order_disclaimer`（"Internal record only. No payment, transfer, contract signature, or ERP update happens here."），场景不可覆盖；`provenance !== 'live'` 时叠加 `SimulatedBadge` | 7,8 | `renderPublicText` 引擎级模板；13 的变更单组件快照 | 用户把内部记录当合同 |
