| INV-74 | `resolveRound` 优先级：任一 `clarify` 需人回答 → `needs_input(clarify)`；任一 `escalate` 过策略检查 → `needs_input`（`escalate(infeasible)` → 按 `relaxationOrder` 选收件人的 `infeasible` 请求；`escalate(needs_tradeoff)` → customer 的 `agent_escalated` 请求，05 §5.10 / §5.11.2）；全部 `recommend_accept` ∧ `isExecutable` → `pending_approval`；customer `counter` 可行 → 下一轮 proposer 回合（反馈只带 counter 的 candidateKey、不带 customer 快照里的 O 标号，provider 看到的 O 标号在其新快照构建时分配；`counter` 与 `reject` 不短路，finance 仍评估 base）；其他（reject / 可代答 clarify）→ 下一轮；`roundNo === maxRounds(3)` 且无合格提案 → customer `rounds_exhausted` 请求（`choose_candidate` / `keep_as_is` / `end_run`）；provider 所选候选被规则阻断 → 不插提案、不消耗版本号、不花评估调用，`turn.outcome.blockedCandidateKey` 记录后直接下一轮只反馈 `blocked`；可行集只有 1 个候选仍跑完一轮 | 4,8 | 纯函数 `resolveRound`（05） | 轮次用尽无请求死路；"全员 recommend_accept 但 evaluate 失败"无分支 |
| INV-75 | `setup` 期的写入（`invites.accept` / `briefs.confirm` / `budget.setCap` / `catalog.confirm` / `catalog.retire` / `ledger.recordBaseline`）只写来源、不 bump、不开 run，末尾调用 `openIfReady`；最后一个就绪条件（04 §4.2.1：三席齐、三方简报已确认且硬字段齐、≥ 1 个 confirmed item、baseline 已录）满足时，同事务 `setup → open` → `bump(cause: 'room_opened')`（cv 0 → 1，首行 `constraintRevisions`）→ `react()` → `startRunTx(cause: 'room_opened')`；该系统路径不受排空与 `run_starts` 节流阻断（排空时首回合 `waitingReason: draining`）；触发它的那次写入照常受 `constraint_writes` 节流，被拒则整体回滚、简报不写入 | 4 | `openIfReady`（04 M2）；`roomReadiness` 缺口逐项显示负责角色 | 多一个无出口的等待态（D12 否决 R-H 的理由）；setup 阶段反复确认耗尽 run 上限（candidates2 判词）；排空把约束 / 简报写入一起回滚 |
| INV-76 | run 终态互斥且无出边：`executed`（仅经 INV-47）、`superseded`（经 `constraints.bump`、`requestRenegotiation` 或 `runs.reconcile` 发现 D06 被破坏时的修复）、`ended_no_agreement`（`end_run` / 请求过期 / 轮次用尽且 customer 放弃）、`canceled`（`runs.cancel` / `rooms.close` / 运维 `rooms.forceClose`）；进入终态同事务：open 请求 → `superseded` 或 `expired`，非终态 turn → `stale`，其 `active` 提案 → `stale`（bump）或 `superseded`（其余，04 P2b），running attempt 留给 G1 拒收（不 cancel） | 4,6 | `RUN_TRANSITIONS` 穷举单测；`setStatus` 迁移断言 | `failed` 再被 `maybeAdvance` 拉回 negotiating（run-lifecycle r02） |

### 1.10 时间与值域

| ID | 谓词 | 核心 | 落点 | 违反后果 |
| --- | --- | --- | --- | --- |
| INV-77 | 房间时区 `rooms.timeZone` 建房后固定；`rooms.localDate`（`YYYY-MM-DD`）只由 `rooms.create` 与 `clock.rollLocalDate` / `rollLocalDateTx` 写；规则检查与物化在 query 与普通 mutation（含 approve 的纵深防御重算与执行）中一律读 `rooms.localDate`，只有推进日期处用 `todayInTimeZone(Date.now(), room.timeZone)` 计算（`Intl.DateTimeFormat` 时区支持待验证 V-D2）；其余 mutation 读 `Date.now()` 只用于判定过期；query 永不读 `Date.now()`；引擎输入 `today: IsoDate` 由调用方传入（= `rooms.localDate`） | 4 | 引擎纯度 lint；`clock.rollLocalDate` 每小时 cron（或各房间本地午夜 `runAt`） | query 缓存语义不刷新（rules-engine r09）；跨时区日期错一天 |
| INV-78 | 日期与金额在任何边界都按同一函数比较：日期字典序（`IsoDate`），金额整数分；提案 `deliveryDate` 与目录 `leadDays` 的关系在插入时固定（INV-36）；`extend_deadline { date }` 与 `sharedFacts` 日期都过窗口校验（INV-18） | 4 | `core/engine/dates.ts` 单一实现 | 字符串与 `Date` 混比；`4800-01-01` 合法写入 |
