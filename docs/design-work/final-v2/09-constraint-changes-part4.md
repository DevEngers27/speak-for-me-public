- **陈旧页面**：customer 在步 2 之前打开的 v1 审批页在步 8 之后点 Approve → `approvals.record(v1, expectedConstraintsVersion: 1)` 在 A-G3 失败（v1 已 `stale`、run#1 已 `superseded`）→ `approval.not_current`，不写行；即使 run 仍在等审批，A-G5 也会以 `approval.stale` 拒绝（canon D02 的 TOCTOU 防线）。
- canon D27 早稿写"3 条审批 stale"：spike 的纯函数把三个必需席位都计为未生效；在本系统里若 finance 已批，v1 早在第三票时执行，所以实际是 2 条 `stale_approve` + finance `pending`（审批槽位原因 `approval.stale ×2 + approval.missing_role ×1`，canon §1.5：`missing_role` 只作槽位原因）；canon D27 已按此改写（C57，9.14 Q5 / Q6）。
