# 17 演进路线

原则：每个扩展点先说明它要求引擎接口提供什么；能在不改引擎表的前提下完成的，只追加场景联合成员或新增 helper。

## 17.1 第二个场景：活动预算（event budget，FX-01）

| 维度 | 活动预算 | 引擎接口是否足够 |
| --- | --- | --- |
| 角色 | organizer（主办）、vendor（场地/餐饮供应商）、finance | 是：`roles[]` 声明 |
| 目录 | vendor 发布的套餐（场地、餐饮、设备），带人数区间与可用日期 | 是：`catalogContentV` 追加成员 |
| 硬约束 | organizer：日期范围、最少人数、必需项目；vendor：最低消费、可用日期；finance：上限 | 是：字段声明 + `evaluate` |
| 条款 | 套餐组合 + 人数 + 日期；价格 = 单价 × 人数 + 固定费用 | 是：`termsV` 追加成员；`deriveTerms` 计算 |
| 候选 | 组合 × 人数档位 × 日期：需要剪枝（先固定必需项、日期按可用集合） | 是：`enumerateCandidates` 自带上限 |
| 任务 | 每个套餐一项，指派 vendor | 是：`deriveTasks` |

验证方式：第二场景接入时不修改任何引擎表与引擎函数签名；若必须修改，说明接口设计有缺口，先修接口再接场景。

## 17.2 外部集成（ERP、会计、项目管理）

- 采用 outbox：执行事务额外插入 `outbox { operationKey, target, payload(公开或目标系统有权看到的字段), status }`；internal action 投递，按 `operationKey` 向外部系统做幂等写入；失败重试与告警由投递器负责。
- 执行事务本身永不调用外部系统；对外只承诺"至少一次投递 + 幂等键"，不宣称 exactly-once（P-05）。
- 转账、电子签名不在路线内（核心 7）；若将来接入，必须是人在外部系统中的独立动作。

## 17.3 通知

- 邀请、"轮到你批准"、人工请求、run 失败的邮件/站内通知，经同一 outbox 投递。
- 通知正文只含房间标题、角色、动作类型与链接，不含任何金额、日期或私密字段（与公共文本同一套模板纪律）；收件人只限席位本人。

## 17.4 多模型

- `packages/agent-claude` 抽象为 `ModelAdapter { buildRequest, call, classifyError, mapUsage }`；协议层只依赖 `AgentContext` 与输出 schema。
- 每个调用点的模型与 effort 进入配置（已有 `AGENT_MODEL` 白名单，扩展为按调用点）。换模型的前提：在同一组 fixture 上跑 L5 评估（结构性质 + 注入套件 + 延迟）。

## 17.5 预算与承诺

- 多房间共享项目预算：新增房间之上的 `budgets` 实体，执行事务读写该预算文档（OCC 串行化跨房间执行），已承诺额按预算汇总；房间内的 finance 简报改为引用预算。
- 修订链与冲销：`changeOrders.revisesChangeOrderId`、负向承诺（冲销），要求放宽"金额非负"并给冲销单独的审批策略。
- 审批阈值：`requiredApprovers(terms)` 按金额返回不同集合（例如超过阈值需要第二名 finance），快照机制不变。

## 17.6 时间相关约束

- 报价有效期（`validUntil`）与审批有效期：到期时由被调度的 mutation 触发 `bumpConstraints(cause: "expired")`，与其他约束变化走同一流程。
- 截止日临近提醒：通知扩展点。

## 17.7 规模与运行时

- 全局并发控制：若 429 频繁，引入 `@convex-dev/workpool` 的 `maxParallelism`；回合守卫与记录不变。
- 更大目录：枚举剪枝与上限；候选数仍限 12。
- 若协议演化为长时间等待外部事件，再评估 `@convex-dev/workflow`（需接受确定性约束）。

## 17.8 产品能力

| 能力 | 前提 |
| --- | --- |
| 席位更换（错人占席、人员变动） | 定义"旧席位用户的决定如何处理"：建议更换即约束变化（cv +1），旧决定全部 stale |
| 一席多人（两名 finance） | 席位内的"代表人"概念；完成判定仍按角色集合 |
| PDF/邮件导入 | 抽取管线复用：只预填、逐项确认 |
| 变更单导出 | 打印视图优先；CSV 需防公式注入（T-25） |
| 用户自助删除 | 与核心 6 的取舍需要法律与产品决定（18） |
| 组织与 SSO | 不用 Clerk Organizations 表达房间角色（inputs/04 §3.4）；组织只用于"谁能建房" |
| i18n | 模板已集中在引擎与场景；需要 locale 参数进入 `renderEvent` |
| 用户验证与度量 | 访谈外包/采购/财务协调人员（V-03）；度量得到有效提案的时间、人工干预次数、硬约束违规数（应为 0）、成本，报告样本数 |
