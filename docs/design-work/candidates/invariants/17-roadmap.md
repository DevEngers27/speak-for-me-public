# 17 演进路线与扩展点

原则：每个扩展都先回答"它会不会破坏某条不变量；若要放宽，用什么新的不变量替代"。下表按建议顺序排列；v1 范围见 01 §4。

## 1. 第二个场景：活动预算（event budget，FX-01）

- 角色 organizer / venue / finance；条款 = 场地套餐 + 餐饮行 + 活动日期；预算与台账沿用引擎。
- 对引擎的要求（v1 已满足）：角色、字段、回合计划、检查集、可行性、取舍、执行派生、模板都由 `ScenarioModule` 提供（06 §12）；三处联合 validator（简报内容、条款、代理输出 / 请求选项）各加一个成员；事件 payload 的场景部分加成员。
- 需要新增的引擎能力：无。若第二场景需要"按行交付日期"或"多个提议方"，`turnPlan` 扩展为多 proposer 轮转，RN-3 守卫不变。
- 验收：第二场景在不修改 `convex/engine/**` 的前提下通过全部不变量测试。

## 2. 通知（邀请、待审批、待回答）

- v1 只在应用内显示待办。下一步：邮件通知，由 mutation 在同事务插入 `notifications` outbox 行，独立 action 投递并以 (eventSeq, recipient) 为幂等键。通知内容只用模板与房间受众字段（EV-3 同样适用），私密数值永不进邮件。

## 3. 外部集成（ERP、会计、电子签名的"只读同步"或"草稿推送"）

- 执行边界（核心 7）不变：系统仍不转账、不签署。集成形态是 outbox：`executeIfReady` 在同一事务追加 `outbox{ kind: "erp_change_order", executionId, idempotencyKey = operationKey }`，投递 action 至多一次 + 重试表 + 人工对账界面。外部失败不影响内部执行记录；对外只承诺"至少尝试、可对账"，不宣称 exactly-once（P-05）。

## 4. 已执行变更单的修订与取消

- 新增 `executions.revisesExecutionId` 与台账调整条目（`commitments.kind = "adjustment"`，允许负数但 Σ 仍 ≥ 0）；VAL-1 改为"单条调整可为负，累计承诺非负"，EX-5 不变。修订本身仍是一次完整的协商 → 审批 → 执行。

## 5. 预算账户跨房间共享

- 引入房间之上的 `budgetAccounts`（finance 拥有），commitments 挂到账户；EX-5 变为账户级不变量。并发执行跨房间时，M-ROOM 不再足够：执行 mutation 必须同时 patch 账户文档（账户级写锁）。CS-4 的快照改为账户台账。

## 6. 席位与身份

- 一个角色多名用户（例如两名 finance）：席位（participant）与成员（seat members）分开，审批规则变为"席位内任一 / 全部成员"；ID-4 改写为"同一用户不得占两个必需席位"。
- 同一用户多角色（小企业里 finance 即项目负责人）：只能在显式的"单人兼任"房间模式下允许，且审批完成判定要求兼任者对每个角色分别确认；默认关闭。
- 成员移除与房主转移：移除需处理其进行中的决定（视为 withdraw）与请求（cancelled）。

## 7. 代理能力

- 代理提出目录外新选项 → 落为 provider 草稿行（unconfirmed）→ provider 确认后成为报价（核心 4 不变：未确认不进规则）。
- 付款条件作为第四个协商维度：finance 规则字段 + 条款字段 + 检查 + 模板。
- 每字段的委托授权（mandate）：委托人细粒度设定代理可以用哪些私密字段做出可见动作；P6 由"全有"变为按字段。
- 抽取扩展：PDF 报价、邮件线程（模型侧能力以平台文档为准，待验证）。

## 8. 多模型与模型选择

- `engine/llm` 已是唯一的模型适配层；多提供方需要：统一的请求形状约束、usage 字段映射、结构化输出能力探测。调用点级模型选择（例如评估回合用较小模型）作为配置项，需要用户决策（18）并以同一组 fixture 的质量与延迟对比为依据。
- 服务端回退（fallbacks）在验证与结构化输出兼容后开启（10 §8）。

## 9. 编排与规模

- 若出现跨多日的多步骤自动化（例如定时提醒、到期自动关闭请求），评估 `@convex-dev/workflow`；若 Anthropic 429 频繁，引入 workpool 的 `maxParallelism`。
- 放宽场景规模上限（请求项 > 8）时，`enumerateFeasible` 改为带 `exhaustive` 标记的启发式搜索，非穷举时不得声称"无可行方案"（SIM-2）；取舍请求措辞改为"未找到"。

## 10. 产品与合规

- 用户访谈与采用路径验证（V-03、F01.4 的假设）；度量面板对外展示前完成样本量要求。
- 报价有效期之外的"审批有效期"（例如批准 14 天后失效）。
- 删除与匿名化（18 开放问题）；数据导出（变更单 PDF，CSV 需防公式注入）。
- i18n：模板已集中，可按查看者语言渲染。
- 原生移动应用（响应式网页之后）。
