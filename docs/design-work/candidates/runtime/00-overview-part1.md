# 00 概览（part1）：系统一页纸、设计原则、核心保证

> 入口：`00-overview.md`（核心保证表与分片索引）。分片：part1 本页；part2 术语表、与原方案的主要差异、文档读法。
> 本设计的主视角是**协商运行时与可靠性**：先把一次协商 run 的生命周期与全部失败模式列清楚（10），再由 run / turn / attempt 的持久化、守卫、重试与超时预算、用量记录推导 schema（03）、状态机（04）与 API（12）。

## 0.1 一页纸

- **做什么**：多方 AI 协商工作台。每方把目标与约束私密交给自己的代理；代码枚举出满足所有硬约束的候选方案；代理在候选之间按各自委托人的软偏好协商并给出建议；人批准一个不可变的提案版本；全部必需审批到齐的那一次事务里原子写入变更单、预算承诺与任务；任何约束变化让旧审批派生失效，并在同一事务里取代当前协商、开始重新审批 / 重谈 / 向具体的人请求取舍（01）。
- **栈**：Next.js 16（App Router）+ Convex 1.48（数据库、函数、调度、订阅）+ Clerk 7（身份）+ `@anthropic-ai/sdk` 1.1.0（只在 Convex action 中调用 `claude-opus-5-5`）。不引入任何 Convex 组件或代理框架（ADR-01）。
- **引擎 + 场景**：引擎提供房间、席位、简报容器、约束版本、协商运行时、审批、执行骨架、事件；场景插件（首个：软件范围变更）提供字段、目录、候选枚举、规则、模板、提示与执行派生（02 §2.4、06 §6.8）。
- **运行时**：自建 scheduler 链。一次 run 由若干 turn 组成，每个 turn 有若干 attempt；每个 attempt 与它的 watchdog 同事务登记；模型结果先 record 再 apply；apply 有六条守卫，任一不满足即作废；重试只在 attempt 层，受 turn / run / 房间 / 每日四级预算约束；熔断与总开关让代理不可用时系统退化为人工选择而不是卡住（10）。

## 0.2 设计原则

| # | 原则 | 体现 |
| --- | --- | --- |
| P1 | 代码决定、模型建议、人批准 | 候选由代码枚举（ADR-05）；模型只选候选键；审批只来自人的 mutation |
| P2 | 每条不变量只有一个写入口 | `bumpConstraints`、`startRunTx`、`insertProposal`、`executeIfReady`、`scheduleAttempt`（03 §3.14） |
| P3 | 能派生的不存储 | 提案状态与可执行性、审批状态、邀请过期都是派生（04 §4.1） |
| P4 | 先持久化，再应用 | record → apply 两阶段写回（ADR-04） |
| P5 | 只有一层重试，所有预算有上界 | SDK `maxRetries: 0`；四级调用预算（ADR-03、ADR-18） |
| P6 | 在数据源头投影隐私 | 同一组投影函数服务界面查询与代理上下文；多角色可读的文档不存私密数值（07） |
| P7 | 代理不可用时退化到人 | 评审 fail-open、提议 fail-closed + 手动提案（ADR-10） |
| P8 | 两个方案都完整时选简单的 | 不用 workflow / workpool；预算放进 finance 简报而不是另建两张表（ADR-12）；不做 token 流式（ADR-28） |

## 0.4 运行时与可靠性要点（10 的摘要）

| 失败 | 系统行为 |
| --- | --- |
| 模型超时、限流、5xx | attempt 层按类别退避重试（≤ 2 次），每次请求一行用量 |
| action 被平台中断 / 部署打断 | watchdog 在 deadline 判 timed_out 并重试；部署无需等待活跃 run 结束 |
| 输出格式错误 / 拒答 / 截断 | 各重试一次（格式错误附中途 system 消息，截断提高 max_tokens）；仍失败按回合类型 fail-open / fail-closed |
| 约束在回合中途变化 | 同事务取代 run；迟到结果判 stale，只记用量 |
| 重复调度、并发 run | 当前 attempt 租约 + 单一 run 创建入口 + OCC |
| 写回失败 | record 失败交 watchdog 重试；apply 失败不重新调用模型，直接判失败 |
| 额度耗尽、密钥失效 | 熔断打开，所有房间退化为手动选择；运维修复后重置 |
| 费用失控 | 四级预算 + 总开关 + 供应商花费上限 |
