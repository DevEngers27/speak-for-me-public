# 18 决策记录与开放问题（part3）：其余 ADR、输入冲突裁决、开放问题、待验证

> 分片清单见 part1。

### ADR-23 软约束不使审批失效（ruleKey 判定）
- **背景**：F09.1【改写】；Role A 的 saveBrief 一律不递增（RA-B02），另一个极端是任何简报确认都递增。
- **决定**：场景为每个角色定义 ruleKey（规则相关字段的规范串）；只有 ruleKey 变化才递增约束版本。软偏好、备注、披露的变化生成新简报版本、影响之后的代理上下文，但不让审批失效。
- **后果**：既修复 RA-B02，又避免"改一句备注就要三方重签"。

### ADR-24 首个场景 fixture：REPORTS 由"必需"改为"重要（软）"
- **背景**：Role A fixture 中 items 1、2 都必需（RA-F01）；在 $4,800 下只剩一个候选，代理没有可谈的空间；审查要求至少有可行重谈、需要取舍、不可行三条路径（F14.4）。
- **决定**：LOGIN 必需、REPORTS 重要、EXPORT 可选 + 加急费条款；保留 README 的全部金额（$1,400 / $900 / $4,900 / $4,800）；"两项都必需"保留为变体 D。
- **后果**：主线出现真实取舍（保 REPORTS 还是保首选日期）；$800 恰好等于余量，主线落在 ≤ 边界上（RG-14 与变体 E 做对照）。

### ADR-25 修订已执行的协议：同一房间开新 run
- **背景**：GAP-13；Role A 要求新建房间（RA-S05），README 说"start a new flow and preserve history"。
- **决定**：`runs.requestRenegotiation` 在最近 run 已执行时可用，新 run 基于包含该执行的约束版本；旧执行、变更单不变。修订链（supersedes、负金额调整）留到 17。
- **后果**：历史连续、不需要复制简报与目录；已执行条目记入约束快照的 `executedItemKeys`，新 run 只在剩余范围内枚举候选，避免对同一条目重复承诺（06 §6.5）。

### ADR-26 允许把预算上限调到已承诺额以下
- **背景**：Role A 拒绝这种输入（RA-R10）；F06.3 建议进入 needs_input。
- **决定**：允许并警告；之后无候选，只问 finance（14 变体 C）。
- **后果**：系统如实记录现实中的预算削减，而不是拒绝录入真相（核心 8）。

### ADR-27 三个代理都调用模型；finance 代理只做评审表态
- **背景**：F01.1、F10.17：算术交给代码后 finance 代理与确定性校验重叠；但 G2 要求"三个隔离代理调用模型"。
- **决定**：finance 保留一个 effort low 的评审回合（表态与私密理由），不做任何算术；产品文案如实描述"代码检查预算，finance 代理只给建议"。
- **后果**：每轮多一次低成本调用；若用户决定去掉（Q-02 的一部分），只需把 finance 从 `reviewerRoles` 移除，协议不变。

### ADR-28 不做 token 级流式；回合级进度
- **决定**：界面订阅回合与尝试的状态（drafting / retrying / slow / failed / done）；未经校验的模型输出从不展示。
- **后果**：没有高频写入；与"只展示校验后的结果"一致（inputs/04 §4.9）。
