## 17.2 扩展点与对引擎接口的要求

| 扩展 | 价值 | 对引擎的要求 | 现有接口是否已够 |
| --- | --- | --- | --- |
| 第二场景 event_budget | 验证通用性 | 无（06 第 6.15–6.16 节已逐项检验） | 够：新增插件 + 三处注册 |
| 通知（邮件 / Slack：邀请、待审批、请求） | 多日审批不必盯屏 | `outbox` 表（事件 → 通知任务），投递 action 带幂等键；通知内容只用模板与公开数据；用户通知偏好 | 需新增 outbox 与投递 action；不改现有状态机 |
| 外部集成（ERP、会计、项目管理） | 执行结果落到外部系统 | 执行事务只追加 `outbox`（不调外部）；适配器 action 投递并记录回执；失败重试与人工对账；永不在执行事务内调用外部系统；外部 exactly-once 不承诺 | 需新增 outbox；执行事务增加一次插入 |
| 变更单修订（冲销、改金额、取消任务） | 真实项目会变 | 台账冲销条目（负向或 `reversal` kind）、执行记录的 `supersedesExecutionId`、任务 `cancelled` 状态；修订本身走提案 → 签核 → 执行 | 需扩展台账与执行；`assertCents ≥ 0` 改为按条目类型 |
| 一席多人 / 分级审批 | 两名 finance、超额才需 CFO | `seatCount > 1`、签核策略 `requiredWhen(terms, view)`；成员变化走 `bumpConstraints` | 需扩展席位与签核快照 |
| 跨房间共享预算 | 一个项目多次变更 | 房间之上的 `budgets` 实体；执行事务锁预算文档（OCC）；规则视图的台账来自预算而非房间 | 需新实体；插件接口不变（仍读 `ledger.committedCents`） |
| 多方联合放宽的取舍 | 单方放宽无解时 | `tradeoffs` 返回组合选项与"需要多人同意"的请求组 | 需扩展请求组语义 |
| 代理提出目录外新选项 | 代理创造性 | 代理动作 `suggest_item`（无价格）→ 给作者本人的请求 → 人补价并确认 | 新增动作与请求意图；受 05 校验框架约束 |
| 报价/签核有效期策略 | 现实中报价会过期 | 已有 `validUntil` 与 `SOURCE_EXPIRED`；签核有效期需新增可选 `expiresAt` 与派生状态 | 部分已够 |
| 付款条件作为第四维度 | finance 的里程碑偏好 | 插件条款增加付款计划字段与检查；模板与 UI 片段 | 够（插件内） |
| 多模型 / 按调用点换模型 | 成本与延迟 | `modelConfig` 已按调用点配置；新增提供方需 `callModel` 适配接口 | 调用点配置已够；提供方适配需抽象 |
| workpool 限流 | 高并发时的 429 风暴 | 把 `runTurn` 改为经 workpool 调度，`maxParallelism` | 运行时内部替换，不影响协议 |
| 文件导入（PDF、邮件） | 更快建简报 | `extractDraft` 支持文件；仍只产出草稿建议 | 够（抽取路径） |
| 导出 / 打印变更单 | 归档与对外沟通 | 打印视图优先；CSV 需公式注入防护；明确标注"内部记录，非合同" | 够（只读 query） |
| 界面多语言（zh-CN） | 用户群 | 模板与界面字符串按 locale 增补 | 够 |
| 账户删除与数据导出（合规） | 合规 | "清除私密字段内容、保留结构与审计链"的作业 | 需新运维函数 |
| 原生移动端 | 审批便利 | 现有 API 已按查看者投影，可直接复用 | 够 |

## 17.3 产品验证活动（非系统功能）

- 访谈有外包、采购或财务协调经验的人：记录流程、痛点、据此做出的改动（V-03）。
- 验证 H1/H2 假设（客户方是否有独立预算负责人；provider 是否愿意进房间）。
- 度量：得到首个可执行提案的时间、人工介入次数、硬约束违规（应为 0）、模型成本，报告样本数（15）。
