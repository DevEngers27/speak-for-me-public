# 07 · 跨候选设计的共性缺陷（来自 candidates2 的 15 名评委，2026-10-24）
> 5 份独立设计被 15 名评委打分，invariants 维度全部只有 3.3–4 分，因为评委在每一份里都构造出了违反任务书核心的反例。下面按共性归类，供统一口径裁决；原文见 design/judging/candidates2.json 与各候选目录。**这些缺陷大概率同样存在于 candidates/ 的 4 份设计和专题深潜中。**

### 执行后的后续 run 重复承诺已执行范围（2 条）
- 【场景插件接口优先 / invariants】Core 5 / I9 (09 §2, 12 ledger.addExternalEntry). The function is explicitly marked non-idempotent ('one entry per call') and has no over-cap check. A finance double-click writes two external commitments. Adding $1,500 at committed $4,000 / cap $5,000 gives Σ $5,500 > cap, which breaks the 'Σ entries ≤ cap always holds' claimed by ADR-09. I9 is only asserted at execution time.
- 【代理协商质量与评测优先 / invariants】执行之后仍可重新协商并重复承诺同一范围。文件：04-state-machines.md R1、08-approval-execution.md §8.4 第 7 步、09。操作序列：run#1 执行 v1 LOGIN+REPORTS|rush（committed $4,900）→ customer 再次调用 runs.start（currentRunId 已清空，readiness 仍为 true）→ analyzeFeasibility 判定 infeasible → 给 finance 发"Raise the cap to at least $5,350" → finance 选 set_budget → bump → 新 run 再次提议 LOGIN → 三方批准，生成第二张变更单和承诺，LOGIN 任务重复。I5 只以 (proposalId, cv) 去重；brief 和房间生命周期都没有"已承诺范围"的概念，系统会主动引导重复采购。
