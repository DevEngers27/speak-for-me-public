## 1. 目标与范围

### 1.1 要证明的东西（按任务书第 3 节的八条核心逐条对应）

| 核心 | 需要的证据 | 主要测试层 |
| --- | --- | --- |
| 1 私密委托 | 任何身份调用任何公开 query 的返回值、任何 WebSocket 负载、事件表、日志里都不出现他方私密值；代理上下文组装不含他方私密字段 | L0（`buildAgentContext`）、L1（逐 query 披露）、L3（WebSocket 负载扫描）、L2（日志扫描） |
| 2 代理只建议 | `recommend_accept` 永远不写入 approvals；代理动作集合外的输出被拒 | L0、L1 |
| 3 人批准具体版本 | 约束版本或提案内容变化后旧审批失效、执行被拒 | L1 |
| 4 代码负责校验 | 编造 itemKey、模型给出金额、超预算、晚于截止日、必需项缺失都被确定性代码拒绝；`stop_reason` 非 `end_turn`、解析失败不被当作"无动作" | L0、L1 |
| 5 执行幂等且原子 | 并发最后两票、重复执行调用、客户端重发只产生一条 execution / commitment 与一组 tasks | L1（串行语义）+ **L2（真实部署并发，唯一能证明 OCC 的层）** + L3（UI 双击） |
| 6 历史不可篡改 | 提案只插入；审批撤回是追加；约束变更后旧记录仍可读 | L1 |
| 7 执行边界 | 代码中没有任何外部写调用；执行只写三张内部表 | L0（静态检查）、L1 |
| 8 不伪造 | seed、stub、录制回放产生的记录带 `isSimulated` / `authorKind` 标注并在界面显示 | L1、L3 |

### 1.2 范围

- 测试：纯函数单测、convex-test（含身份模拟与调度推进）、真实 dev / 集成部署上的并发与幂等探针、三账号三会话端到端、隐私金丝雀、注入用例、过期结果拒绝、真实模型评估（结构性质 + 延迟）。
- 运维：环境分离（个人 dev / PR 预览 / 共享集成 / 生产）、密钥与配置归属、seed / reset 授权、可观测性（事件、用量、成本、延迟、日志纪律）、CI 流水线、部署与排空。
- 不在范围：负载测试（v1 用户量极小，只测并发正确性，不测吞吐）、混沌工程、多区域、SLA 合同、外部告警平台选型（只给接口）。

### 1.3 不做的事（反过度设计）

- 不引入第二个测试运行器、不自建测试 DSL、不做快照测试（模型文本不可复现，快照只会制造噪声）。
- 不为测试在生产代码里加"测试后门"公开函数；测试专用函数一律 `internal*` 且受部署层级守卫。
- 不另建指标存储：用量的事实来源是 10-agent-runtime 定义的只追加表 `modelCalls`（run-lifecycle 专题 D6），本专题只从它派生指标。
- 不存成本：只存 token；成本在读取时按代码里带 `asOf` 的估价表换算并标"估算"（F03.9 已决定不存 `costEstimateMicros`）。

## 2. 决定与理由

每条：决定 → 理由 → 被否决的备选 → 带来的不变量。

### TD-1 单一测试运行器：Vitest
- 决定：L0 纯函数与 L1 convex-test 都用 Vitest（精确版本，安装时取已发布 ≥ 2 周的版本，pnpm 锁定）；L3 端到端用 Playwright Test。
- 理由：convex-test 的官方用法建立在 Vitest 之上（`edge-runtime` 环境 + 假时钟推进调度，inputs/04 §1.12，API 名称待验证）；一个运行器覆盖两层，配置与 CI 最简单。
- 否决：Node 自带 `node --test`（F16.1 的零依赖方案）——无法承载 convex-test，且 `.ts` 测试导入 `.ts` 有 TS5097 问题；Jest——与 convex-test 的推荐组合不符。
- 不变量：`pnpm test` 不访问网络、不需要 Convex 部署、不需要任何密钥（CI 的 PR 闸门因此可在 fork PR 上运行）。

### TD-2 五层金字塔，每层只证明它能证明的东西
| 层 | 载体 | 证明什么 | 不能证明什么 | 何时跑 |
| --- | --- | --- | --- | --- |
| L0 纯函数 | Vitest（node 环境） | 规则、算术、日期、披露裁剪函数、上下文组装、模型输出解析、模板渲染、成本估算 | 任何 Convex 语义 | 每次提交 |
| L1 后端模拟 | Vitest + convex-test（edge-runtime 环境） | 状态机迁移、鉴权、逐 query 披露、调度链（回合、看门狗、重试）、过期结果拒绝、幂等的**串行**语义 | 并发 / OCC、真实限额、真实运行时差异、部署打断 | 每次提交 |
| L2 部署探针 | Node 脚本 + `npx convex run --identity`，对个人 dev 或共享集成部署 | OCC 下的唯一性与幂等、调度器真实行为、action 超时、日志零泄露、默认运行时能否承载 SDK | 浏览器行为 | 合并到 main 后夜间；改动执行 / 审批 / 调度代码的 PR 手动触发 |
| L3 端到端 | Playwright，三个 Clerk 测试账号三个浏览器上下文，后端 `AGENT_MODE=stub` | 实时翻转、双击批准只执行一次、刷新后进度保持、WebSocket 负载零泄露、界面上的 simulated 标注 | 模型质量 | 每个 PR（对预览或本地部署） |
| L4 模型评估 | Node 脚本对集成部署 `AGENT_MODE=live` | 真实模型输出的结构性质、注入鲁棒性、p50/p95 延迟、token 与估算成本 | 确定性（不可复现） | 手动 / 每周；改提示、改 schema、换模型或 effort 时必跑 |

- 理由：convex-test 串行执行、不模拟 OCC（inputs/04 §1.12，F08.5），把并发结论写在 L1 上就是伪证；模型不可复现（F16.4），不能进 PR 闸门。
- 不变量：**任何"并发 / 幂等已验证"的结论都必须引用一份 L2 证据记录**（part4 §3.6 的 `ConcurrencyEvidence`）；L1 的同类用例只能标为"串行语义"。

### TD-3 模型调用必须经过一个可替换的接缝
- 决定：所有 Claude 调用经 `convex/agents/modelClient.ts` 导出的 `callModel(req): Promise<ModelCallResult>`；运行时按 `AGENT_MODE`（`live | stub`）选择实现。L1 用 `vi.mock` 替换该模块注入"脚本化响应"（含 `max_tokens`、`refusal`、解析失败、超时、迟到返回）；L3 用 `stub`（确定性 `findFeasibleOffers`，`authorKind: "rule"`，F10.7）；只有 L4 与生产用 `live`。
- 理由：模型行为是唯一不可控输入；把它隔离成一个函数，其余 100% 可确定性测试。`vi.mock` 不需要在生产代码里放测试分支。
- 否决：在部署上放 `AGENT_MODE=scripted` 并从数据库读脚本——给生产代码增加一个可被误开的后门；录制回放 HTTP（nock 一类）——绑死 SDK 的 HTTP 细节，SDK 升级即失效。
- 不变量：`AGENT_MODE` 缺省为 `stub`；`live` 需要同时存在 `ANTHROPIC_API_KEY` 与 `AGENTS_ENABLED=true`；生产以外的层级若无 key 一律 `stub`。`vi.mock` 在 convex-test 模块图中是否生效：待验证（退路见 part3 §3.3）。

### TD-4 并发与幂等证据只在真实部署上取得
- 决定：L2 用三种互补方法对同一不变量取证：(a) N 个并行的 `npx convex run <fn> --identity` 进程；(b) 只在非生产层级存在的 `internalAction` 探针 `devProbe.parallel`，在一个 action 里 `Promise.all` 多个 `ctx.runMutation`；(c) L3 的 UI 双击。每次产出一条结构化证据（方法、N、部署名、提交、结果计数、是否观察到 OCC 重试）。
- 理由：(a) 最贴近真实客户端但 CLI 冷启动让重叠窗口不确定；(b) 重叠更紧（action 内每次 `runMutation` 是独立事务，inputs/04 §1.4；是否真正并行发出：待验证）；(c) 覆盖客户端重发路径。三者都通过同一个不变量断言才算通过。
- 否决：只在 convex-test 里 `Promise.all`（不模拟 OCC）；压测工具（与目标无关）。

### TD-5 隐私证据 = 构造保证 + 金丝雀扫描，二者都要
- 决定：(1) 构造层：`buildAgentContext(role, …)` 与每个公开 query 的返回值都由按查看者裁剪的纯函数产生，L0 / L1 断言他方字段缺失；(2) 观测层：fixture 在每个私密位置放唯一金丝雀（含数值金丝雀，例如 finance 上限 `$4,817.31`，见 part4 §3.8），跑完整流程后扫描所有查看者可达的输出与日志，按"允许出现位置白名单"判定。
- 理由：只做 (1) 会漏掉错误信息、事件摘要、日志这类旁路；只做 (2) 无法覆盖未跑到的分支。
- 不变量：金丝雀只能出现在白名单 `(table, field, ownerRole)` 中；扫描器对白名单外任何命中直接失败。

### TD-6 注入用例验证"看不到就泄露不了"，模型鲁棒性只作次要指标
- 决定：确定性部分（L0 / L1）断言：他方自由文本永远不进入本方代理上下文（F05.3）；对他方可见文本只由模板从结构化字段生成；即使脚本化模型输出包含预算数字，公共历史与他方视图中也不出现。真实模型的注入表现放 L4，记录为指标而非闸门。
- 理由：私密值根本不在 provider 代理的上下文里，注入成功也拿不到；系统安全不能依赖模型拒绝。
